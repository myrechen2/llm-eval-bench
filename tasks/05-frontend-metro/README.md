# 任务 05 · 前端应用:地铁线路规划器(WebDev 类)

**对标:** WebDev Arena / Design Arena / "vibe coding" 类评测 —— 根据需求说明一次性构建一个完整、好用、好看的 Web 应用。同时包含一个必须**算对**的核心算法(带约束的最短路),由隐藏用例自动判分。

## 你要做什么

构建一个**单文件** Web 应用 `submissions/<SUBMISSION_ID>/05-frontend-metro/index.html`:一个城市地铁线路图 + 路径规划器。示例线网数据见 `network.json`(虚构城市)。

### 硬性约束

* **单个 `index.html` 文件**,所有 CSS / JS / 示例数据内联。直接双击(`file://`)打开即可运行。
* **不得引用任何外部资源**(CDN、字体、图片、接口),不得发出任何网络请求。
* 不得有控制台报错。
* 原生 JS/CSS 即可;如需框架请自行内联(不推荐)。

### 数据格式(`network.json`)

```jsonc
{
  "name": "滨海市轨道交通(示例)",
  "transferTime": 4,                 // 默认换乘耗时(分钟)
  "stations": [
    {"id": "S06", "name": "中央广场", "x": 470, "y": 350, "transferTime": 7}  // 可选:该站的换乘耗时(可以为 0)
  ],
  "lines": [
    {"id": "L1", "name": "1号线", "color": "#d7263d", "loop": false,
     "stations": ["S01", "S02", "..."],   // 沿线站点顺序,同一条线内站点不重复
     "times": [3, 3, "..."]}              // 相邻两站间的运行分钟数;非环线长度 = 站数-1;
                                          // 环线(loop=true)长度 = 站数,最后一项为末站回到首站
  ]
}
```

* 列车双向运行,两个方向耗时相同。
* `x, y` 是绘图坐标(任意正数,需要你自适应缩放到画布)。
* 站点 `id` 是任意字符串(不要假设格式),`name` 可能包含空格。
* 可能存在两条线路在同一对相邻站之间并行(耗时可能不同)。可能存在与其它站点不连通的站点。

### 路径规划规则(必须精确实现)

* 乘客可以在起点乘坐任意一条经过起点的线路,**上车不计时间**;到达终点即结束。
* 总耗时 = 所乘区间运行时间之和 + 每次换乘的换乘耗时。在站点 `s` 从一条线换到另一条线的换乘耗时 = `s.transferTime`(若该字段存在,**包括 0**),否则为全局 `transferTime`。
* **最短时间模式(`"time"`)**:先最小化总耗时,相同时再最小化换乘次数。
* **最少换乘模式(`"transfers"`)**:先最小化换乘次数,相同时再最小化总耗时。
* 起点 = 终点:耗时 0、换乘 0。无法到达:返回 `null`。

### 功能需求

1. **线路图**:按坐标绘制全部线路(线路颜色、环线闭合)和站点;换乘站(≥2 条线经过)要有明显区别;站名标注尽量不重叠、清晰可读;能看出每条线的名称(图例或标注)。
2. **选择起终点**,两种方式都要支持:
   * 在地图上点击站点:第一次点击设为起点,第二次设为终点;两者都已设置时再次点击则重新从起点开始。
   * 输入框 `#origin-input`、`#destination-input`:输入站名有联想/候选;**输入完整站名后按 Enter 即选中该站**。
3. **模式切换**:`#mode-time`(默认选中)、`#mode-transfers`,切换后立即重新规划。
4. **结果展示**:总耗时、换乘次数、分段行程(每段:线路名+颜色、起止站、经过几站),换乘处提示"在 X 站换乘 Y,约 N 分钟"。结果容器为 `#route-summary`,并带有属性 `data-total-time`(整数分钟)和 `data-transfers`(整数);无法到达时给出友好提示并移除这两个属性。
5. **地图高亮**:路线在地图上高亮,其余线路弱化;起点/终点有标记。
6. **交换按钮** `#swap-btn`:交换起终点并重新规划。
7. **响应式**:在 1440×900 桌面和 390×844 手机竖屏下都好用,手机上**不出现横向滚动条**。
8. 地图上可点击的站点元素需带属性 `data-station-id="<站点 id>"`。
9. 加分项:适配系统深色模式、键盘可操作、地图缩放/平移、过渡动画等。

### 测试接口(必须提供)

页面加载完成后暴露:

```js
window.metroBench = {
  // 用新的线网替换当前线网,并重新渲染整个界面(清空已选起终点)。
  loadNetwork(network) {},
  // 纯计算,同步返回结果;不要求修改界面。
  route(fromId, toId, mode /* "time" | "transfers" */) {
    // 返回 null(不可达)或:
    return {
      totalTime: 32,          // 整数分钟
      transfers: 2,
      path: ["S03", "S04", "...", "S44"],          // 依次经过的站点 id(含起终点,换乘站只出现一次)
      legs: [ {line: "L1", from: "S03", to: "S04"}, {line: "L4", from: "S04", to: "S18"}, "..." ]
      // legs 覆盖整条 path,相邻 legs 线路不同;每个 leg 内 path 上相邻两站必须是该线路上相邻的两站
    };
  }
};
```

评审会用**隐藏的线网**(含环线、站点换乘时间为 0、并行线路、不连通站点、数百个站点的大线网等)调用这个接口并校验结果。单次 `route` 调用在 300 站规模下应在 200 ms 内完成。
