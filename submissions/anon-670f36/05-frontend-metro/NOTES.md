# Task 05 — 地铁线路规划器设计说明

## 1. 设计思路
* **单文件零依赖实现**：所有样式、SVG 绘图、路网数据与交互逻辑均内联于 `index.html`，双击 `file://` 即可运行，无任何外部资源与网络请求。
* **界面与交互**：桌面端采用左侧控制面板 + 右侧自适应 SVG 地图画布的双栏布局；移动端（≤860px）自动切换为纵向堆叠布局且无横向滚动条。支持深色模式自动适配（`prefers-color-scheme: dark`）与手动切换，支持鼠标/触摸拖拽平移、滚轮与按钮缩放、图例单线高亮、输入框联想与回车直选、键盘焦点操作。
* **视觉排版**：对平行共线段按垂直法向偏移分离绘制；换乘站使用双环标识；采用基于线段穿插与矩形碰撞打分的贪心 8 方向标注算法自动避让站名与轨道；起终点徽标自动避开站名方向放置于顶层。

## 2. 路径规划算法
* **状态空间建模**：为每个 `(stationId, lineIdx)` 建立乘车状态节点，沿线路相邻站点（含环线首尾闭环边）添加双向运行边（换乘增量为 0）；在换乘站（≥2 条线经过）额外引入中心虚节点 `(stationId, HUB)`，从各乘车节点到 HUB 添加耗时为站点换乘耗时（显式区分 `0` 与未设置，仅在 `typeof transferTime === "number"` 时覆盖默认换乘耗时）、换乘次数为 `1` 的有向边，从 HUB 回到各乘车节点添加 `(0, 0)` 有向边。
* **启发与优化**：相比在 $k$ 线换乘枢纽构建 $O(k^2)$ 换乘完全图，HUB 节点将边数降为 $O(k)$ 且禁止同线零代价自换乘。起点所有可用线路状态以 `(0, 0)` 入堆，终点任一线路状态首次出堆即终止。
* **双模式与复杂度**：使用二叉最小堆 Dijkstra，在 `"time"` 模式下以 `(totalTime, transfers)` 为字典序关键字，在 `"transfers"` 模式下以 `(transfers, totalTime)` 为关键字。实测 320 站路网单次 `route` 查询耗时约 1 ms（远低于 200 ms 要求）。

## 3. 已知局限
* 站名标注避让采用贪心局部选位，在极高密度网络（数百站密集聚簇）且未放大视图时仍可能存在局部标签紧凑；可通过滚轮/按钮放大视图查看。
* SVG 路径按原始站间直线段绘制，未额外做 45°/90° 八方向拓扑拉直，以忠实保持输入坐标结构。
