# Task 05 · 地铁线路图与路径规划器说明

## 设计思路

* **单文件零依赖**：所有 HTML、CSS、SVG 渲染、交互逻辑及默认线网数据均内联于 `index.html`，双击 `file://` 即可离线运行，无任何外部资源请求。
* **界面与视觉**：
  * 桌面端采用左侧控制/结果栏 + 右侧全屏交互式 SVG 线路图；移动端（如 390×844）自动切换为上下堆叠布局，严格防止横向滚动条。
  * 根据站点坐标范围自适应计算 SVG `viewBox`，支持滚轮缩放、拖拽平移与重置视图；自动适配系统深色模式并提供手动主题切换按钮。
  * 换乘站采用双圈高对比度样式，普通站采用线路色空心圆；并行区间自动施加法向偏移避免完全重叠；站名标注依据相邻线路夹角选择最空旷的 8 方向位置并加背景描边以减少遮挡；点击/悬停图例可高亮对应线路。
* **交互完备性**：支持地图点击选站（起点 → 终点 → 重新选起点）、输入框模糊/精确联想与 Enter 直接选站、起终点一键交换（`#swap-btn`）、最短时间/最少换乘即时切换（`#mode-time` / `#mode-transfers`），以及 `#route-summary` 上的 `data-total-time` / `data-transfers` 属性维护。

## 路径规划算法

* **状态空间建模**：将状态定义为 `(stationId, lineId)`，即“位于某站且正处于某条线路上”。
  * 起点以成本 `(0, 0)` 将经过起点的所有线路状态入队（上车不计时间与换乘）。
  * 乘车转移：沿同一线路双向移动至相邻站（环线自动首尾闭合），耗时加区间运行时间，换乘次数不变。
  * 换乘转移：在同一站点切换至其他线路，耗时加 `station.transferTime`（显式判断 `typeof === "number"` 以正确处理 `0` 分钟换乘）或全局 `network.transferTime`，换乘次数加 1。
* **多目标最短路**：使用手写二叉最小堆运行 Dijkstra：
  * `"time"` 模式按 `(totalTime, transfers)` 字典序最小化；
  * `"transfers"` 模式按 `(transfers, totalTime)` 字典序最小化。
* **复杂度与验证**：在 300 站规模网格线网下实测单次查询耗时 `< 5 ms`；已对默认线网全部 2738 组起终点×双模式组合，以及 0 分钟换乘、并行线路、环线、不连通站点、起终点相同等边界用例完成合法性校验。

## 已知不足

* 在超过 140 站的超大型线网中，为避免画面过于拥挤，默认仅显示换乘站站名（普通站仍可通过点击、悬停或输入框搜索选中）。
* 站名避让采用基于局部相邻线段夹角的启发式策略，在极端密集的自定义坐标布局中仍可能存在少量文字轻微重叠。
