# Task 05 · 地铁线路图与路径规划器说明

## 1. 整体设计思路

- **单文件零依赖架构**：整个应用完全封装在单个 `index.html` 中，所有 CSS 样式、SVG 矢量地图渲染引擎、二叉最小堆（`MinHeap`）、多准则 Dijkstra 路径规划器和示例线网数据均内联，无需任何外部 CDN、字体或网络请求即可在 `file://` 协议下直接双击运行。
- **响应式与深色模式适配**：
  - 桌面端（`1440×900`）采用左侧固定控制与行程详情面板（`380px`）+ 右侧自适应矢量地图画布的双栏布局；
  - 移动端（`390×844`）自动切换为单列纵向流式布局，控制区与地图区上下排布，全局设置 `overflow-x: hidden` 与弹性宽度约束，杜绝横向滚动条；
  - 使用 CSS 变量与 `@media (prefers-color-scheme: dark)` 原生支持系统浅色 / 深色主题切换。
- **SVG 自适应线路图与智能防重叠标注**：
  - 根据所有站点的 `(x, y)` 坐标动态计算包围盒与边距，生成自适应 `viewBox`，支持任意正数坐标范围以及鼠标滚轮、拖拽平移与按钮缩放；
  - 针对环线（`loop: true`）自动将末站与首站闭合绘制；针对同一对相邻站之间的多条并行线路，沿法线方向施加微小垂直偏移，使并行线路清晰可辨；
  - 换乘站（`≥ 2` 条线路经过）采用双层同心圆靶心节点，普通站采用对应线路主题色的单圆环节点，每个站点包含透明扩大热区便于点击且带有 `data-station-id="<站点 id>"` 属性；
  - 站名标注通过 8 方向候选包围盒碰撞检测（Greedy Label Placement）自动挑选与已有站点和文字重叠面积最小的方位，并加描边光晕（`paint-order: stroke`）保证可读性。

## 2. 路径规划算法说明

- **状态空间建模**：
  将列车乘行状态建模为二元组 `(stationId, lineId)`，表示“当前位于站点 `stationId` 且正处于线路 `lineId` 的列车上”：
  - **起点初始化**：由于起点上车不计换乘时间，从起点 `fromId` 经过的所有线路 `L` 的相邻下一站 `(nextStation, L)` 直接以 `{time: travelTime, transfers: 0, hops: 1}` 入堆；
  - **同线乘行转移**：沿当前线路 `lineId` 前往相邻站 `nextStation`，耗时增加区间运行时间 `w`，换乘次数不变；
  - **换乘并继续乘行转移**：在任意非起点车站 `u` 从当前线路换乘到经过 `u` 的另一条线路 `otherLine` 并前往其相邻站 `nextStation`，耗时增加 `u` 的换乘耗时（优先取 `u.transferTime`，包含 `0`；未定义时取全局 `network.transferTime`）加上下一区间运行时间 `w`，换乘次数 `+1`。这种“换乘+乘行一步”合并转移从根本上消除了在同一站点原地换乘或终点无效换乘的冗余路径。
- **多准则字典序最短路（Lexicographic Dijkstra）**：
  - `"time"` 模式按 `(time, transfers, hops)` 字典序比较；
  - `"transfers"` 模式按 `(transfers, time, hops)` 字典序比较；
  - 使用手写二叉最小堆 `MinHeap` 维护待扩展状态，时间复杂度为 $O((|E| + \sum_{s} \deg_{L}(s)^2) \log |V|)$。在 300 站规模线网下，单次 `route` 查询耗时通常在 `1~3 ms` 以内，远低于 `200 ms` 要求。

## 3. 已知不足与取舍

- 站名防重叠采用 8 方向贪心局部最优放置，在极端高密度站点聚簇时仍可能有轻微文字交叠（可通过地图缩放功能放大查看）。
